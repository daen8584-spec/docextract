# 0002. Use Drizzle ORM for data access and migrations

- Status: Accepted
- Date: 2026-11-05

## Context

The application needs typed database access, versioned schema migrations and the ability to drop to raw SQL for operations such as row locking and queue claims. Prisma was evaluated first. Its CLI depends on native engines and packages that are not published for every platform, and installation failed on an Android arm64 development environment. Its query API also makes PostgreSQL-specific constructs (`FOR UPDATE SKIP LOCKED`, partial indexes, `ON CONFLICT ... WHERE`) awkward to express.

## Decision

Use Drizzle ORM with the `node-postgres` driver. The schema is defined in TypeScript (`db/schema.ts`) and migrations are SQL files generated by `drizzle-kit` and committed to the repository. Raw SQL is used through Drizzle's `sql` template where the query builder is not expressive enough, with all values passed as bound parameters.

## Consequences

- Queries are type-checked against the schema with no code generation step.
- The tooling is plain TypeScript and runs on any platform Node.js supports.
- Generated SQL is predictable and close to what is written, which makes performance and locking behavior easy to reason about.
- Migrations are reviewed as SQL. Data migrations that the generator cannot express, such as converting enum values, are written by hand in the migration file.
